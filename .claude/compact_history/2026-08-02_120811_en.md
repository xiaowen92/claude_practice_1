## Observe (key understanding of Claude Code / LLM underlying logic)

1. **The LLM never executes your tool function**: the server-side LLM only "tells you which tool to call" (returns a ToolUseBlock) and "reads the result and generates an answer". Executing the function is 100% in your local code. Reason: the LLM is on Anthropic's server and cannot reach your runtime, filesystem, database, or internal API. The whole point of tool use is to let tools execute in your own environment.

2. **Distinguish the two "user" meanings**:
   - Human end-user — the user of your app, who just sends "what time is it".
   - API `role: "user"` — a protocol label that carries both human messages and tool_results.
   They share the name but are not the same thing. Sending tool_result with `role: user` is a protocol requirement, not "the human typing in the result".

3. **The two `create()` calls are independent; the API is stateless**: the first call sends messages and gets back a ToolUseBlock; the second call must resend the **complete messages** (user question + assistant tool_use + user tool_result, 3+ messages). The API does not remember the previous call, so the second call sends the full history, not just the tool_result.

4. **`stop_reason='tool_use'` is the loop's control signal**: the LLM uses this field to say "I've stopped, it's your turn to call the tool". The tool runner decides whether to continue the loop by checking this field; the loop ends when `stop_reason` becomes `end_turn`.

5. **Both the assistant tool_use message and the user tool_result message must be appended**: missing the assistant tool_use message causes a 400 (the tool_result has no matching tool_use). Neither can be omitted.

6. **There are only two roles, which determine message ownership**: `assistant` = what the LLM produces; `user` = what is sent into the LLM. So both the human question and the tool_result are `role: user` in messages.
