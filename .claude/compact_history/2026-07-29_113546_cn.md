## Observe（关于 Claude Code / LLM 底层逻辑的关键理解）

1. **Standard tool use 是"你和模型来回四步",模型自己不执行你的函数**：
   - Step 1 (你): `user` 提问
   - Step 2 (模型): `assistant` 返回 `[ToolUseBlock(...)]`,`stop_reason: tool_use` —— 模型只是"告诉你该执行哪个 tool",不会真的跑
   - Step 3 (你): 在 Python 里真正执行函数,把结果包成 `tool_result` block 塞进一条 `user` 消息回传
   - Step 4 (模型): 读到工具结果,`assistant` 生成最终自然语言回答
   - 漏掉 Step 3 直接跳 Step 4,API 会报 "tool_use 后面缺 tool_result" 的 400。

2. **`tool_result` 是一种 content block,必须包在 `content: [...]` list 里**,而不是摊在 message 最外层。API 靠 block 里的 `"type": "tool_result"` 识别它;字段名 (`type` / `tool_use_id` / `content` / `is_error`) 是规范固定的,`tool_use_id` 必须等于 Step 2 那个 `ToolUseBlock` 的 `id`,否则报错。

3. **`response.content` 的 block 数量和类型由模型每轮动态决定**,不能假设 `content[0]` 一定是 text 或一定是 tool_use —— 应遍历 `content` 按 `block.type` 分发。按位置写死(如 `content[0].text`)会在 block 类型不符时踩 `AttributeError`。

4. **tool 的 `input` 空不空由 schema 决定,与模型版本无关**：`required: []` + 有 default → 模型传 `{}`;有 required 参数 → 模型必须填。
