## Observe(关于 Claude Code / LLM 底层逻辑的关键理解)

1. **LLM 从不执行你的 tool 函数**:server 端的 LLM 只"告诉你该调哪个 tool"(返回 ToolUseBlock)和"读结果生成回答"。执行函数这一步 100% 在你本地 code。原因:LLM 在 Anthropic server 上,碰不到你的 runtime、文件系统、数据库、内网 API。tool use 的意义正是让工具在你自己的环境里执行。

2. **两个 "user" 要分清**:
   - 真人 end-user —— 你 app 的使用者,只发一句"现在几点"。
   - API `role: "user"` —— protocol 标签,既装真人消息,也装 tool_result。
   两者同名但不是一回事。tool_result 用 `role: user` 回传是 protocol 规定,不是"真人把结果打进去"。

3. **两次 `create()` 调用相互独立,API 无状态**:第一次发 messages 拿到 ToolUseBlock,第二次必须把**完整的 messages**(user 问题 + assistant tool_use + user tool_result 共 3 条以上)重发一遍。API 不记得上一次,所以第二次不是只发 tool_result,而是发全部历史。

4. **`stop_reason='tool_use'` 是 loop 的控制信号**:LLM 用这个字段说"我停手了,轮到你调工具"。tool runner 就是靠判断这个字段决定要不要继续 loop;当 `stop_reason` 变成 `end_turn` 时 loop 结束。

5. **assistant tool_use 消息和 user tool_result 消息都要 append**:少了 assistant 的 tool_use 那条,API 会报 400(tool_result 找不到对应的 tool_use)。两条缺一不可。

6. **role 只有两种,决定了消息归属**:`assistant` = LLM 吐出来的;`user` = 送进 LLM 的。所以真人问题和 tool_result 在 messages 里都是 `role: user`。
